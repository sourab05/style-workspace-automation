# Token Release Sync

Handles the half of token change detection that Component.json cannot see.

```
Component.json changed      → WHICH properties are tokenized   → token-slot-delta
global token files changed  → WHICH refs exist, WHAT they equal → this skill
```

Backing script: `scripts/token-release-diff.ts`.

---

## IMPORTANT: Agent rules

- **Run the dead-ref sweep before triaging any failure as a product bug.** An unresolvable reference
  makes the test compare against `undefined`, which is indistinguishable from a genuine regression in
  the report. Skipping this check is how days get lost chasing a phantom.
- **Fix dead refs upstream, never locally.** If the tokens came from a sync, a local edit to
  `tokens/**` is overwritten by the next sync. The fix belongs in `wavemaker-foundation-css`.
- **A value-only change needs no framework edit but does need a retest.** `token-slot-delta` correctly
  reports nothing for these — that is not a miss. Do not "fix" the registry in response.
- **Every claim needs tool output.** Quote the actual ref and file:line.
- **Run in the user's terminal, not a sandbox.**

---

## Commands

```bash
# All four checks
npx ts-node scripts/token-release-diff.ts

# Dead-ref sweep only — offline, instant, no previous revision needed
npx ts-node scripts/token-release-diff.ts --dead-refs

# Compare against a specific previous token tree
npx ts-node scripts/token-release-diff.ts --against tokens.backup-1785415776000

# Web tokens, or machine-readable
npx ts-node scripts/token-release-diff.ts --platform web
npx ts-node scripts/token-release-diff.ts --json
```

Exit codes: `0` clean · `20` dead refs found · `21` breaking ref changes found.
Report: `reports/token-release-diff.json`.

## The four checks

### 1. Dead refs — highest value

Every `{…}` in every Component.json, verified against the generated `token-values-mobile.json`.

**Live example, found on the current tree:**

```
carousel  {border.style.solid}
   tokens/mobile/components/carousel/carousel.json:71,123,175,581
   → likely meant {border.style.solid.value}
navbar  {body.large.line-height}
   tokens/mobile/components/navbar/navbar.json:205
   → likely meant {body.large.line-height.value}
```

Both are missing the `.value` suffix — 5 slots resolving to nothing. Both are **upstream** defects
(synced from `stage-ai@ca7357eb`), so they belong in a foundation-css bug report.

The script suggests a fix by probing near-misses: missing `.value`, and dot/hyphen confusion
(`{border.style.solid}` vs `{border-style.solid}`). A ref with no near match is more likely a
*removed* global token — check #2 confirms.

### 2. Global ref-set diff

Compares the global token ref set against a previous revision. The comparison source is a
`tokens.backup-<ts>/` directory left behind by `sync-foundation-tokens.ts --apply`, or `--against`.

A **removed** ref that is still referenced by a Component.json is breaking — and it fails in the
confusing way described above rather than loudly.

### 3. Retest scope after value changes

When `{radius.sm.value}` goes 4px → 6px, nothing structural changes. `token-slot-delta` reports
nothing, correctly. But every test asserting that value now expects a different number.

This check answers "which widgets reference a ref whose value moved?" and emits a ready-to-run
command:

```bash
npx ts-node scripts/trigger-jenkins-build.ts \
  --widgets <affected> --target "All — Web (Canvas+Preview) + Mobile (Android+iOS)"
```

This is change class 4 in
[the architecture doc](../../../docs/09-AI-WORKFLOW-ARCHITECTURE.md#4-the-change-impact-matrix) — the
most common change in a release, and the one where doing nothing to the framework is right but
retesting is mandatory.

### 4. Token map integrity

`tokens/token-values-mobile.json` is generated by `npm run build:token-map`. If a rebuild silently
drops entries, everything downstream compares against `undefined`. This check asserts every global
token on disk is present in the map.

**Case-sensitivity note:** the generator writes `Tokens/` (capital T) while consumers read `tokens/`.
On macOS these are the same file; on a case-sensitive filesystem (Linux CI) they are not. The script
probes both spellings, but this is worth remembering if CI behaves differently from a laptop.

## Why the dead-ref sweep guards the coverage invariant

The framework's two dimensions obey different rules:

| Dimension | Rule |
|-----------|------|
| **Token slots** | **100% — every slot must be tested.** An invariant ([tokenSlotGenerator.ts:37](../../../src/playwright/tokenSlotGenerator.ts#L37)) |
| Appearance × variant × state | Sampled (orthogonal, ~25,000 → ~2,500) — a deliberate trade |

A dead reference is the one failure that **breaks the slot invariant while appearing to satisfy it**.
Coverage counts a slot as covered once a test case is *generated* for it; a dead ref means that test
case ran and compared against `undefined`. So `coverage: 100` can be reported while those slots
verified nothing.

That makes `--dead-refs` a precondition for believing any coverage figure — not an optional extra.

Retest scope, by contrast, names **widgets**, and variant sampling still applies to it. Phrase it as
"retested under the orthogonal variant sample", never as exhaustive. `carousel` and `tabbar` use full
Cartesian rather than orthogonal because their state-dependent styling made sampling unsafe — the
precedent for any widget where a variant-specific regression is suspected.

## When to run

| Situation | Command |
|-----------|---------|
| After `sync-foundation-tokens --apply` | full run — the backup is the comparison point |
| Before triaging any failure as a product bug | `--dead-refs` |
| After `npm run build:token-map` | full run — check #4 confirms the rebuild |
| A test returns `undefined` / empty for a slot | `--dead-refs` first |
| A whole token type fails across widgets | full run — suspect a renamed global token |

## Relationship to other skills

| Skill | Boundary |
|-------|----------|
| `sync-foundation-tokens` | brings new tokens in; run this after it |
| `token-slot-delta` | Component.json slots. Reports nothing for a value-only change — by design |
| `triage-token-failures` | should call `--dead-refs` before classifying anything as a product bug |
| `run-token-tests` | consumes the retest widget list from check #3 |
| `test-with-ai` | orchestrates; routes global-token changes here (change class 5) |
